# StudyQuest 网盘目录结构逻辑映射设计文档

本文档描述了 StudyQuest 平台如何将网盘（AList / WebDAV）中的物理目录结构，智能映射为数据库中逻辑的“课程-章节-课时”三层结构，以及其中支持的“目录穿透”、“名称微调”等设计逻辑。

---

## 1. 核心模型定义

数据库中的物理存储与逻辑展示完全分离，所有目录层级均为逻辑层级：

```
┌────────────────────────────────────────────────────────┐
│                        Course                          │  (课程：最外层聚合容器)
└──────────────────────────┬─────────────────────────────┘
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
   ┌──────────────────┐        ┌──────────────────┐
   │    Chapter A     │        │    Chapter B     │     (章节：可选的逻辑分组，可直接挂载课时)
   └─────────┬────────┘        └─────────┬────────┘
             │                           │
       ┌─────┴─────┐               ┌─────┴─────┐
       ▼           ▼               ▼           ▼
   ┌───────┐   ┌───────┐       ┌───────┐   ┌───────┐
   │ Ep 1  │   │ Ep 2  │       │ Ep 3  │   │ Ep 4  │     (课时：底层播放节点，绑定视频真实网盘路径)
   └───────┘   └───────┘       └───────┘   └───────┘
```

- **Course (课程库)**:
  - 属性包括：标题、适用年级、科目、封面、标签 (Tags)。
  - 是前端呈现给用户（学生）的最小独立学习单元。
- **Chapter (章节)**:
  - 属性包括：所属课程 ID、章节标题、章节描述、排序字段。
  - **可选存在**：课程下可以不设章节，直接悬挂课时（Episode）。
- **Episode (课时)**:
  - 属性包括：所属课程 ID、所属章节 ID（无章节时为 0）、课时标题、视频真实网盘相对路径 (`video_relative_path`)、文件哈希 (`file_hash`)、文件大小、播放时长。

## 2. 网盘物理路径与逻辑结构的映射逻辑

在进行网盘扫描和导入时，系统根据以下规则智能识别并允许用户微调映射关系：

### 2.1 智能角色识别规则
当用户在管理后台选择某网盘路径进行扫描时，系统会递归扫描该目录（默认最多支持 5 层，以避免触发网盘 API 频次限制），并采用以下默认策略：
1. **根目录节点**：默认识别为 **Course (课程)**。
2. **中间目录节点**：
   - 若该目录下只含有子目录，或混合含有子目录与文件，默认识别为 **Chapter (章节)**。
   - 用户可以手动将其修改为“穿透/跳过 (Skip)”或自定义章节名称。
3. **叶子节点（视频文件）**：
   - 过滤网盘中的非视频文件，仅将视频格式（mp4, mkv 等）识别为 **Episode (课时)**。
   - 默认根据文件名和字母/数字顺序自动生成 `SortOrder`。

### 2.2 中间层目录穿透（跳过）设计
实际网盘目录层级可能非常深，或者存在冗余的中间嵌套文件夹（例如：`课程根目录/第一阶段/基础篇/视频.mp4`）。
- **穿透逻辑 (Skip/Penetrate)**：
  - 用户在预览树中，可勾选“跳过当前文件夹”。
  - 处于“跳过”状态的目录节点在执行导入时**不会**在数据库中创建 `Chapter` 记录。
  - 该目录下的所有子视频文件会“向上浮动”，直接归属到其**最近的非跳过上级节点**（可以是上层的某个 Chapter，或者直接归属于 Course 根下）。
- **示例说明**：
  ```
  网盘物理结构：
  [Folder] 物理极简课 (识别为 Course)
    └── [Folder] 第一部分 核心基础 (识别为 Chapter 1)
          └── [Folder] 视频分流缓冲 (用户勾选：跳过/穿透)
                ├── 课时01.mp4 (逻辑上直接挂在 Chapter 1 下)
                └── 课时02.mp4 (逻辑上直接挂在 Chapter 1 下)
  ```

### 2.3 导入前的微调与确认
为了防止“入库即混乱”的痛点，导入设计为**向导模式（先预览树，确认无误再导入）**：
- **名称重命名**：在执行导入前，管理员可以在网页树状图上直接双击修改识别出来的 Course 名称和 Chapter 名称。
- **选择性导入**：可通过树节点复选框，排除不需要导入的文件夹或单个视频文件。
- **标签一键绑定**：导入时可勾选已有标签，或输入新标签，批量应用到新建的 Course 上。

## 3. 数据库冗余与物理隔离

1. **绝对路径与相对路径**：
   - 课时中存储的是网盘的**相对路径**（相对于存储源根目录）。
   - 视频文件不需要在网盘中真实发生移动，所有的课程与章节分类均在数据库中以逻辑外键的形式存在。
2. **容灾与重定位（双保险检索）**：
   - 如果用户在网盘中重命名或移动了视频文件夹，导致数据库中记录的物理路径失效，系统在播放时会通过 `FileHash`（优先）或 `文件名+文件大小`（兜底）自动在网盘中全盘检索，重新定位并自动修正数据库中的 `video_relative_path`，保障逻辑结构的稳定性。
