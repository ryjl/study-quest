## 已搁置(评估后决定不做 / 暂不做)

### LLM chat 多轮对话

学生在 AI tab 里和 agent 多轮讨论一节课,答案带视频时间戳跳转("你说的通分在 12:38 讲过")。

- **为什么搁置**:当前 AI 能力(出题/总结/建议/作业/考试/错题本)已形成完整闭环,
  chat 补的是"学生主动提问"维度,但对中小学自用场景价值有限——孩子更需要系统主动
  给题和复习建议,不是和 AI 聊天。工程量大(agent 逻辑 + 流式 UX + 上下文窗口从头做),
  ROI 不高。
- **已清理**:`ChatSession`/`ChatMessage` 表(零使用的空骨架)已删。捡起来要重新建表。
- **什么条件下重新评估**:如果发现孩子学完课后有明确的"想问某个点"的需求,且现有
  总结/建议覆盖不了。

### streaming 输出(SSE)

agent 跑完一次性返回 → SSE 流式输出。

- **为什么搁置**:唯一价值是 chat 的前置(多轮每条等 5-10s 不可用)。chat 搁置后,
  streaming 对现有能力(出题/总结等几十秒生成)是体验优化但非必需,且波及所有 `Chat()`
  调用点,工程不小。
- **什么条件下重新评估**:chat 重新启动时,或现有生成等待体验成为明显痛点。

### rerank(检索重排序)

embedding 检索后加 rerank API 提升精度。

- **为什么搁置**:当前 embedding 是 brute-force cosine(per-episode 几百 chunk 够用),
  数据量不够大时 rerank 无明显收益,徒增依赖。
- **什么条件下重新评估**:课程数/附件显著增多后,检索召回噪声变大时。

## 远期探索(等场景/数据成熟)

### 知识点命名标准化(chunk 标签 / 本体库)

目前 agent 靠 LLM 推理关联 `chunk.text` 描述知识点,"通分"在不同课里是不同 chunk_id。
本体库让知识点有稳定全局 ID,跨课程聚合更准。

- **价值**:跨课程的知识点 mastery 聚合、错题本的知识点维度、课程考试抽题覆盖都更准。
- **为什么不近期做**:中偏大(本体库 schema + admin 标注工具 + chunk 自动匹配),且本体
  粒度要靠应用场景打磨——错题本/考试都上线了,场景有了,但建议先用一段时间,确认现有
  chunk 文本关联的痛点真的出现再投入。
- **依赖**:无硬依赖。

### 附件提取入 content_chunks(PDF / 练习册)

视频配套 PDF/练习册提取后也进 `content_chunks`(`source_type=attachment`),与字幕统一检索。

- **价值**:扩展 RAG 语料,尤其理科(练习册题型丰富)。
- **为什么不近期做**:当前字幕语料够用。等真的发现"题目只能基于老师说的、不够"再做。
- **依赖**:附件上传链路已就绪,schema 已预留(`source_type` 加 `attachment` 值,加枚举零风险)。

### 新题型

- **判断题(judge)**:对/错二选一。50% 蒙中率,适合 warm-up/概念校准,不适合核心检测。
  Scoring 列已支持(`{"correct":true}`),加 `judge` 枚举值即可。工作量小。
- **排序 / 配对题(order/match)**:考过程类知识(历史顺序、实验步骤)。中等工作量,
  主要是前端拖拽 UI 在 PAD 上要打磨。
- **简答题(short_answer)**:开放式问答,LLM 判分。最接近真实考试但判分难,且 PAD
  长文本输入体验差。中偏大。

这些是题型丰富度扩展,不影响现有闭环,按需逐个加。
